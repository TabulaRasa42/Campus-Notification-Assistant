## 根因与纠正

ac834a0七轮预检中的M01把参赛备查证件列为报名材料。返回中的完整引文真实存在，
但模型在说明中擅自补入“报名参赛”；原有应用只验证引文字面匹配，未处理阶段冲突。

先把这轮原始响应接入公开 `NotificationService.extract`，在真实临时SQLite中复现：
错误材料能被确认保存。再缩减为“请报名。参加比赛（请带学生证/校园卡备查）。”，仍复现。
分别只缩短事项名、只改变材料关系状态，错误均保留；因此这两项不是应用漏拦截的根因。
诊断及回归均替换HTTP边界，不读取凭据，不发送请求。

这次补充一项保守的应用规则：

- 事项名及有效事项引文均明确为报名或申请时，才检查其他阶段要求。
- 对材料名在完整原文中的每处出现，检查其所在句；只有材料名前明确写了参赛、报到、
  检录或领取阶段的携带／提交／准备要求，且同句没有当前阶段，才排除该材料。
- 规则不使用材料名称黑名单，不读取标准答案，也不依赖模型自行添加的说明。
  同一证件若在报名时明确要求携带，会保留名称、条件、关系及引用位置。
- 任一处归属不明、当前与其他阶段混合、引文无效，均不自动删除。
  无效引文继续阻止保存；用户明确修正及历史待办不重新过滤。

开发时的反例检查发现并修正了两处误删风险：“现在提交、领取时使用”的材料应保留；
原文另一处要求报名提交同一材料时，也不能仅凭模型选中的参赛引文删除它。
这两项均经历失败测试后修复。
