# Issue #12：当前事项的材料语义（第2步）

日期：2026-10-24。以用户已确认的三部分输出为边界；本文件定义业务含义，不指定生产数据类或 QML 结构，不授权进入第3步实现。

## 输出范围

每条待办仍为事项名、截止日期、所需材料。每份材料可以附带限定说明和原文依据，这些属于材料本身，不是第四栏。完整原文继续可回查。

不把资格、检查动作、名额限制、活动背景或注意事项放进材料栏，不增加通用办理要求模型，不为了容纳这些信息扩大事项范围或新增待办。材料栏不是通知全文摘要。

## 收录判定

对每个候选材料按以下顺序判断，三个条件同时成立才收录：

1. **材料对象**：原文明确出现文件、表单、证明、证件等对象（可以是电子文件）。动作“检查”“体检合格”不是材料对象，不能补成报告。
2. **用户责任**：原文要求办理者准备、提交、上传、出示或携带该对象。仅要求现场签署，没有要求自行准备，不满足此项。明确要求提前下载、打印并携带待签文件则满足；不据此推断文件由谁提供。
3. **事项归属**：该责任直接服务于当前事项。活动现场备查不等于报名提交；同一通知、同一人群或相同主题都不足以建立归属。

事项归属或用户准备责任不明确的候选，不能作为确定所需材料收录；保留原文供核对，不断言无需材料。已明确需要某材料、只有材料的适用条件或选项关系不清楚时，则保留材料及原话，明确待核对，不直接丢弃。

材料为零表示没有找到原文明示的当前事项所需材料，显示“原文未提及”，不显示“无需材料”。本轮不增加区分“原文明确无需材料”与“未提及”的新状态。

## 收录后保留什么

每份材料的可核对含义包括：名称、办理者要做的事、原文明示的适用条件、阶段、数量／格式等必要限定、与其他材料的或／且关系、原文依据。这里是事实清单，不是规定必须增加多少个数据库字段。

- “仅首次申请者”不得省略为所有人；“原件”不得变成复印件，“一份”不能随意改写。
- “A 或 B 任一”保持一个选择组，不显示成 A 和 B 都需要；“A 和 B”不得变成二选一。
- 条件通过“其中”“上述人员”等跨句指代时，依据覆盖先行条件和后句，不只引用文件名称。
- 缺失的适用对象、阶段或数量不补全。未明确不等于全部适用；上下文明示的主体可以使用，但必须有支持它的依据。
- 字面引用匹配不是语义证明。原文中即使存在“体检报告”，也要检查是否要求当前办理者提交，以及是否属于当前事项。
- 允许同义改写，材料名、条件、阶段、动作及选择关系的实质含义必须保持。

## 确认、修正、保存的业务约束（供第3步使用）

合格材料的限定条件和依据应随核对、用户修正、确认保存、重启回查一起保留。用户自行补充的内容须与原文提取区分；无效依据遵守 #3 的修正／补充／移除规则。

不重新解析、静默删除或改写已保存的旧材料。旧记录不明的条件不能自动解释为适用于所有人；具体兼容实现留到第3步。未确认内容不变成待办。

## 明确不做

不新增注意事项，不穷尽结构化所有通知事实，不开发新的材料自动推理／补全能力，不扩展模型供应商，不实现 #4 的多事项编辑和选择性保存。本阶段也不修改应用提示词、模型、服务或界面。
